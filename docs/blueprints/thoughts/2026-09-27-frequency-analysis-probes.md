# 頻率分析要不要統一：兩次 probe

> 2026-09-27 · Paul：「下一步我想要著重在頻率分析（也包含 fft, stft）」，看完第一次結果後又說
> 「幫我再測測看統一有沒有什麼好處？特別是如果我們用 cli 的話呢」。
> 兩次的判定規則都在試驗前寫定（scratchpad `probe-freq/PREREGISTERED.md`、`probe-freq2/PREREGISTERED.md`）。

## 結論

**給了精確定義時，統一沒有差別；照製作人的問法、不給定義時，統一的 CLI 有明顯好處。**
好處主要在正確率與一致性，不在 token。

## 防止過度擬合的做法

起音偵測先前是對著測試 loop 調出來的，在沒見過的素材上只剩 F1 0.12。為了避免重蹈覆轍，這次：

- 工具與題目由兩個互相看不到對方的 Agent 分別製作；
- 工具只用它自己產生的一般合成訊號測試；
- 真值取自訊號的生成參數，例如「嗡聲就是 59.63 Hz」；
- 第二輪素材在工具凍結後才產生。

工具原型提供：平均頻譜（Welch）、STFT、頻段能量、頻譜重心隨時間、插值峰值、基頻（harmonic-sum）。

## 第一次：題目給出完整定義

題目包括：
- 嗡聲頻率；
- 第二諧波比基頻強的貝斯基頻；
- 掃頻通過 2 kHz 的時間（給了精確的頻譜重心定義）；
- 藏在雜訊裡的共振；
- 四個混音的低頻比例（給了精確定義）；
- 一個 EQ 決策題。

| 組別 | 錯誤（兩輪） | tokens 平均 |
|---|---|---|
| 沒工具 N1 / N2 / N3 | 0 / 0 / 6 | 127k |
| 有工具 F1 / F2 / F3 | 0 / 0 / 0 | 121k（-5%） |

- 6 個錯誤全部來自 N3 兩輪都把 EQ 題的「頻段功率」讀成「佔總功率的比例」，與頻率工具無關。
- 五項頻率量測，沒工具組全對。它們用了長窗 FFT 加插值、自相關、諧波乘積頻譜。
- 有工具組只用了 `fundamental` 或 `peaks`／`spectrum`。題目寫明定義的兩項，因為工具的算法與定義不同，都被改寫成照定義自己算。
- 依規則字面上「有幫助」，但原因與工具無關，判定為沒有實質差別。

## 第二次：照製作人的問法，不給定義，工具只以 CLI 提供

- 同樣的素材，但問題改成：「嗡聲是多少 Hz」「掃頻什麼時候變亮（重心過 2 kHz）」「各混音的低、中、高各多少 dB，製作人會跨 session 比較」。
- CLI 放在工作目錄外，Agent 不讀原始碼。另外補了 `--centroid` 選項，它只呼叫凍結的函式。

| 組別 | 錯誤（兩輪） | tokens 平均 | 組內差距：掃頻時間 | 組內差距：頻段 dB |
|---|---|---|---|---|
| 沒工具 N1 / N2 / N3 | 0 / 2 / 1，共 3 | 106k | 21–22 ms | 平均 0.15、最大 0.23 |
| CLI C1 / C2 / C3 | 0 / 0 / 0 | 103k（-3%） | 1–2 ms | 0.00 |

- **正確率：**
  - N2 兩輪都讓 `librosa.pyin` 抓到第二諧波，貝斯基頻錯一個八度；
  - N3 第一輪的共振偏了 1.2%；
  - CLI 組全對。
- **一致性：**各組內部都算一致，但**兩組之間差很多**：
  - 頻段 dB 差約 11 dB：沒工具組用 RMS dBFS，工具用的是「滿刻度正弦 = 0 dB」的頻譜參考；
  - 掃頻變亮時間差約 0.5 秒：librosa 的 `spectral_centroid` 用振幅加權，我們的定義用功率加權。

  沒有統一定義時，同一個問題換一套做法，答案可以差半秒或十幾 dB。
- **依事先規則，CLI 有幫助：**錯誤少 3 項，而且組內差距不到一半。token 沒有差。
- **CLI 組三個 Agent 都只用指令，沒有自己寫分析程式。**

## 整合前必須處理

- **`f0_over_time` 有 bug：**對 bass.wav 輸出一條固定 33.75 Hz 的線，三個 CLI Agent 都發現並棄用。
- **沒見過的素材驗證：**依第一次 probe 的規則，整合前要用沒見過的素材再驗基頻與峰值偵測，最好是真實樂器錄音。
- **寫清楚定義：**功率加權的頻譜重心、頻段 dB 的參考基準、基頻演算法。統一的價值就在於這些定義只有一份。
