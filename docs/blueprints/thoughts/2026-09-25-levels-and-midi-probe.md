# 音量回報與 mido：fresh-Agent 驗證

> 2026-09-25 · 驗證 [levels-and-midi 計畫](../plans/2026-09-25-levels-and-midi.md)（`49a51d9`）。
> 判定規則在試驗前寫定（scratchpad `probe-levels/PREREGISTERED.md`）。兩個 fresh sonnet Agent，
> 任務是 8 小節、90 BPM 的「大聲、有力」beat：鼓 −10、bass −12、keys −14 dBFS RMS，
> 目標音量加總後通常會超過滿格。

## 結論

- **Agent 會看回報的數字並據此修正。**兩人第一版的分軌都嚴重削頂（鼓 81,098 與 40,084 個樣本、
  bass 5,080 與 6,544 個），下一版都修到 0，而且都沒有用 `np.clip`。
- **兩人都用 `mido` 寫 MIDI**，沒有再手寫 MIDI 檔案產生器。
- **發現回報的盲點：** 兩人都用 Pedalboard 的 `Limiter` 解決削頂，這正是我在 skill 裡建議的做法。
  但 `Limiter` 是提高響度用的（JUCE `dsp::Limiter`）：`threshold_db` 不是輸出上限，它會自動
  補增益，並在外掛內部把超過 0 dBFS 的部分直接削平。Tactus 只看得到外掛輸出的結果，所以回報
  0 個削頂樣本，實際上仍有被削平的樣本：
  - L1 mix：23 個；
  - L2 mix：124 個；
  - L2 drums：775 個（它在每個分軌都加了 `Limiter`）。

  實測（0.3 振幅的正弦波）：`threshold_db` −12 時輸出峰值 0.0 dBFS，−0.3 時輸出 −6.4 dBFS。
- **已修正 skill：** 把「或加一個 limiter」改成「調小增益，或在增益前用 compressor 壓住峰值」，
  並寫明 `Limiter` 會補增益、會在內部削頂，所以 Tactus 回報的數字永遠是 0；要用它時，要知道
  它就是會削頂。
- 依事先寫定的判定，V1（交付的 mix 回報 0 個削頂樣本）到 V3 兩人都通過，但 V1 本身因為上述
  盲點，量不到真正要量的東西。

## 還沒解決

Tactus 只能看到超過 ±1 的樣本。如果削頂發生在外掛內部，或作品自己先用 `np.clip` 削過，
數字都會是 0。要讓這種情況也看得見，可以多回報「剛好停在滿格的樣本數」：一段被削平的波形，
會有好幾個樣本停在 ±1.0。這不擋任何東西，只是多一個數字。證據就是這次的 23、124、775 個樣本，
要不要做由 Paul 決定。

## 其他

- 兩人都遇到同一件事，skill 沒寫：稀疏的鼓或 bass 用整段 RMS 去對準目標音量，會被中間的
  靜音拉低，結果增益調得太大。兩人都自己改成只量大聲的區塊。先記下來，還沒有決定要不要寫進 skill。
- 成本：L1 111k tokens／6.3 分鐘，L2 102k tokens／4.2 分鐘。
