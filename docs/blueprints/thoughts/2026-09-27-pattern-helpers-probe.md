## 結論

**Pattern 沒有通過，C1 關閉。**兩組三輪都零錯誤，token 也沒有省：有 Pattern 的組反而多 5%。
修改輪動到的行數也差不多（平均 74 對 76 行）。唯一明顯的差別是最後的原始碼短了約 29%（139 對 195 行），
但事先規則已經說明，程式碼短不算數，要看錯誤、token 或修改量。

| | 錯誤（三輪） | tokens（三輪累計） | 第 2、3 輪修改行數 | 最後 song.py 行數 |
|---|---|---|---|---|
| 沒 Pattern N1 / N2 / N3 | 0 / 0 / 0 | 106k / 117k / 107k，平均 110k | 75 / 63 / 91，平均 76 | 208 / 192 / 185 |
| 有 Pattern P1 / P2 / P3 | 0 / 0 / 0 | 113k / 107k / 128k，平均 116k | 81 / 47 / 95，平均 74 | 165 / 108 / 143 |

第一輪每個 Agent 約 3–3.5 分鐘。第二輪 1–5 分鐘，每個只花 11–15k token。

## 為什麼 Pattern 沒幫上忙

- **原生 Python 本來就寫得很規律。**三個沒 Pattern 的 Agent 都自然寫出以小節編號驅動的規則，例如 `bar % 3 == 0`、
  `rotation = bar - 1`，shaker 用全域 step 取餘數。所以延長到 24 小節時，它們只需要把寫死的小節清單改成通用判斷，
  跟 Pattern 組的改法幾乎一樣。
- **修改量主要是需求本身。**每輪要改的規則數是固定的，不論用哪種寫法，每條規則都得改一兩行。
  Pattern 讓一條規則變成一行，但沒有讓「改一條規則」變得更少行。
- **讀模組要花 token。**Pattern 組第一輪要先讀 `tpattern.py` 的說明，這筆成本在三輪內都沒有攤回來。
- **兩組都沒有改壞不該動的東西。**第二輪指定不准變的 snare 與自由聲部，六個 Agent 都保持逐位元相同；
  第三輪延長後，前 16 小節也都跟第二輪相同。

## 有效性與限制

- **Pattern 組每個操作都用上了。**`steps`、`euclid`、`rotate`、`every`、`on`、`accent`、`cycle`、`degrade`、
  `exclude`、`stack`、`grid`、`realize` 這 12 個，三個 Agent 都用到了，所以不是因為 Agent 不用它才沒差。
- **防止抄答案：**原型說明文件的範例原本幾乎就是第一輪 hat 的答案，派出 Agent 前已改成無關的數字。
- **題目改過一句措辭：**第三輪「兩層在同一個 step 相撞」有歧義，派出前改成「在同一時間點相撞」。
- **評分程式事先驗證過：**用 Pattern 版與純 Python 版兩份參考解確認（三輪零錯誤、輸出逐位元相同），8 種故意做錯的版本也都被抓到。
- **沒測到的：**更長、段落更多的作品；由人來聽、評估「創意豐富度」（自由聲部只有描述性記錄，沒有評分）；
  Agent 多次交接或換人接手。這些情境下 Pattern 是否有價值仍未知。

## 決定

依事先規則關閉 C1：不加 Pattern 模組。Euclidean、旋轉、每 n 小節變化、跨小節循環、seeded 機率，
都以原生 Python 加 `tactus.timing` 表達。重新開啟的條件是：在真實製作中看到反覆出現、而且寫法彼此分歧的 pattern 程式碼，
或出現上面沒測到的情境。
