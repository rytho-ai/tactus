# 時間工具在高負荷下有沒有幫助（cognitive-load probe）

> 2026-09-27 · Paul：看的是 cognitive overload，也就是 Agent 同時顧很多事時，時間計算會不會佔掉注意力；
> 省事也算價值，但不能限制創意。判定規則在試驗前寫定（scratchpad `probe-load/PREREGISTERED.md`）。
> 上一次的[精確題 probe](2026-09-27-temporal-helpers-necessity-probe.md) 只有時間一件事，這次把它放進完整製作。

## 結論

- **沒有證明能減輕負荷。**兩組在時間要求上都零錯誤，製作要求各錯 2 項，token 相差 4%。
  依判定規則（錯誤差距至少 3，或 token 省 30%），兩項都沒達到。
- **創意指標：有工具的組比較貼格子**，不在十六分音符格子上的音分別是 0%、15%、0%；
  沒工具的組是 39%、39%、3%。但程式碼分析顯示這主要是風格，不是 API 造成的。H1、H3 在註解中
  自己決定「全部不要人性化」（題目只要求 hi-hat 不要）；同樣用工具的 H2，一行就加上了人性化偏移。
- **Agent 會自己做出同樣的工具。**沒工具的三人各自寫了 tempo segment 表、小節起點表和取整規則，
  形狀幾乎就是 `tclock`。修改時，有工具的組只動兩行時間設定；沒工具的組要看它自己當初怎麼寫，
  L1 手算每小節起點，修改時得重寫整個函式。
- **下一步：**依這些發現改設計，做第二版並三方比較（見本文最後）。

## 設計

- **兩組：**H 的作品裡有 `tclock.py`，可用可不用，也可以超出它；L 什麼都沒有。每組 3 個 fresh sonnet Agent，
  用 `tactus init` 建立的作品與同一個 crate。
- **第一輪：**一首完整作品，7 項時間要求加 6 項製作要求，音樂內容完全自由。時間要求包括：
  6 秒自由前奏、92 BPM、一個 7/8 小節、依拍位置 92→100 的漸快、climax、100→70 的漸慢、58% swing 的 hi-hat。
  製作要求包括：固定素材、分軌與三條 marker、climax 的鼓約 −12 dBFS、sidechain、濾波與 reverb、交付片段、commit。
- **第二輪（一次多項）：**插入 2 小節 breakdown、漸快提早開始、bass −2 dB、pad 變暗、交付 climax 片段。
- **第三輪（一次多項）：**
  - 漸慢改成最後 6 小節、100→76；
  - swing 62%；
  - climax 的鼓 +1 dB；
  - 前奏改成 4.5 秒；
  - 交付片段。
- **評分：**`check.py` 讀取音檔。小節線對照 `truth.py`（公式計算，並和原型交叉核對過三輪，逐樣本一致），
  另外檢查 swing、各項音量與音色變化、片段範圍、修改點之前的內容沒有移動，以及不在格子上的比例。

## 結果（依檔案核對）

| | 時間要求錯誤 | 製作要求錯誤（第 2、3 輪） | 最終 tokens（平均） | 不在十六分格子上 |
|---|---|---|---|---|
| H | 0 | 2（H3：bass 實際 −3.68 dB 而非 −2；H3 刪掉已交付的 run） | 218k | 0%、15%、0% |
| L | 0 | 2（L2：climax 的鼓只比上一版大 +0.24 dB；L3 刪掉已交付的 run） | 226k（1.04×） | 39%、39%、3% |

- **我的題目有歧義：**第二輪「插入 breakdown、漸快提早」這句，6 人中有 5 人都理解成「總小節數不變」
  （第 6 人拿到的訊息已經附上澄清）。送出一樣的澄清後，全部都改對了。這一項不列入錯誤。
- **兩組在修改時都沒有動到前 8 小節**（以 10 ms 的容許範圍排除人性化偏移跨過邊界的音）。
- **H3 與 L3 刪掉已交付的 run**：違反 skill 第 4 步「交給聽者的檔案要留在原處」。
  它們的舊版本是我從 commit 重建後才拿來比較的。
- **sidechain 的量測不可靠**（所有 Agent 都說做了，我量不出下沉），沒有列入判定。
- 另外有 3 個 Agent 各自踩到 Pedalboard `Limiter` 會自動補增益的問題，都自己解決了。

## 程式碼分析（sonnet 讀了六份作品）

- `tclock` 缺的東西：
  - 用絕對拍數求時間：H1 為了一路連續的 hi-hat，只好呼叫內部函式 `_seconds_between`；
  - 在格子位置上加毫秒偏移：人性化、flam、延後都要自己事後加上去；
  - 完全沒有小節的自由時間段；
  - 以某一段為起點的局部座標：H2 自己寫了 `offset=`。
- 修改時，有工具的組「時間引擎」只改兩行（`TEMPO_POINTS`／`METER_POINTS`），其餘都是音樂內容的表格，
  用哪種工具都得改。

  - 局部座標。
